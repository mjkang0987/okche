# 데이터 구조

iOS(SwiftData)와 안드로이드(Room)가 똑같이 따르는 저장 구조. 백업 파일(JSON)도 이 구조 그대로 쓴다.
화면 기준은 디자인 캔버스 '완성 디자인' 페이지, 기능 기준은 기획 문서. 셋이 다르면 디자인을 먼저 고친다.

> 상태: **확정 (2026-10-27 사용자 검토)**. 바꿀 때는 결정 날짜와 함께 고친다.

## 1. 공통 규칙

### 1-1. 모든 저장 대상이 갖는 칸

| 칸 | 형식 | 뜻 |
|---|---|---|
| `id` | UUID 문자열 | 고유 ID. 기기에서 만든다(Swift `UUID()`, Kotlin `UUID.randomUUID()`). 하나만 있어야 하는 것은 1-5의 고정 ID를 쓴다. |
| `createdAt` | UTC 시각 (밀리초) | 처음 만든 때 |
| `updatedAt` | UTC 시각 (밀리초) | 마지막으로 고친 때. 고칠 때마다 바꾼다. |
| `deletedAt` | UTC 시각 또는 없음 | 지운 때. 1-4 참고. |

- 시각은 모두 UTC로 저장하고, 화면에 보일 때만 기기 시간대로 바꾼다.
- 이름 규칙: 문서·백업 JSON·Swift·Kotlin은 `camelCase`, Room 테이블·열 이름은 `snake_case`.
- 선택지 값은 화면 글자가 아니라 이 문서의 영어 값으로 저장한다(문구를 바꿔도 기록이 깨지지 않게).
- 요일은 ISO 기준 월=1 … 일=7. Swift `Calendar.weekday`는 일=1이므로 `(weekday + 5) % 7 + 1`로 바꾼다. Kotlin `DayOfWeek.value`는 그대로 ISO.

### 1-2. 하루 기준: 새벽 6시

- 하루는 **새벽 6시부터 다음 날 새벽 6시까지**다. 탕약 줄 초기화, '오늘' 기록, 실록 일별 집계가 모두 이 기준을 따른다.
- 기록마다 `day`(`YYYY-MM-DD`)를 저장한다: **기기 현지 시각에서 6시간을 뺀 날짜**. 예: 10/28 새벽 2시 기록 → `day = 2026-10-27`.
- `day`는 기록할 때 계산해 저장한다. 시간대를 옮겨도(해외여행) 이미 남긴 기록의 날짜는 바뀌지 않는다. '시간 바꾸기'로 `occurredAt`을 고치면 그때 기기 시간대로 `day`를 다시 계산한다.
- 6시 전 먹일 시간(예: 05:30)은 **전날 하루의 마지막 차례**다.
- 사진의 '작년 오늘'은 예외로 6시 규칙을 쓰지 않고 찍은 곳의 달력 날짜(`localDate`)를 쓴다.

### 1-3. 누가 남겼는지 모를 때

- 기록의 `petId`는 비어 있을 수 있다 = '누군지 모름'. 기록 목록에서 '누구였는지 정하기'로 나중에 채운다.
- `petId`가 빈 기록은 어느 아이의 실록·통계에도 들어가지 않는다('모르는 채로 두면 어느 실록에도 안 들어가요').

### 1-4. 지우기

- 줄은 남기고 `deletedAt`만 넣는다(백업 병합에서 '지웠음'도 전달해야 해서). 화면·통계·백업 내보내기 목록에선 빼고 본다.
- 화면이 '되돌릴 수 없어요'라고 말하므로 **사진 파일은 바로 지우고, 선택 칸은 비운다**(기록의 `data`는 `{}`). 필수 칸은 그대로 둔다(저장소의 빈칸 금지 제약 때문).
- 약·사료·다과는 지워도 `name`을 남긴다. 지난 실록의 '10/20 탕약 → 프레드니솔론' 같은 글이 빈칸이 되지 않도록.
- 지운 아이에 딸린 기록은 아직 `deletedAt`이 없어도(다른 기기에서 늦게 들어온 것) 읽을 때 뺀다.

### 1-5. 고정 ID (하나만 있어야 하는 것)

기기마다 따로 만들면 백업을 합칠 때 둘이 되는 것은 정해진 이름에서 ID를 만든다: **이름의 UTF-8 바이트를 MD5 한 값으로 만든 UUID v3, 네임스페이스 없음**. Kotlin `UUID.nameUUIDFromBytes(이름.toByteArray(Charsets.UTF_8))`가 이 방식이고, Swift는 CryptoKit `Insecure.MD5`로 같은 바이트에 버전 3·variant 비트를 넣는다(RFC 방식처럼 네임스페이스를 앞에 붙이지 않는다). 두 플랫폼에 같은 이름 → 같은 UUID 테스트를 둔다.

| 대상 | 이름 |
|---|---|
| 함께 쓰는 설정 | `okche:setting` |
| 급식기 자동 기록 | `okche:feeder:{slotKey}` |

- 고정 ID로 만드는 자동 기록은 **같은 ID의 줄이 없을 때만**(지운 줄 포함) 만든다. 지운 줄을 다시 쓰면 되살아나기 때문. `updatedAt`은 만든 때가 아니라 끼니 예정 시각으로 둔다 — 다른 기기가 늦게 자동 기록을 만들어도 보호자가 '남겼어요'로 고친 기록(그 뒤 시각)이 이긴다.

## 2. 아이 (`Pet`)

| 칸 | 형식 | 비고 |
|---|---|---|
| `name` | 글자 | 필수 |
| `species` | `cat` / `dog` | |
| `breed` | 글자 | 목록에서 고르거나 '믹스 · 잘 모르겠어요' |
| `furColor` | 글자 | 치즈·고등어·턱시도·회색 … (캐릭터 털색) |
| `birthDate` | 날짜 또는 없음 | |
| `birthEstimated` | 참/거짓 | '생일을 몰라요 (나이를 어림잡아 넣을게요)' |
| `familyDate` | 날짜 또는 없음 | 가족 된 날 (동행 N일, 가족 된 날 축하). 아이 정보에서 넣는다. |
| `diagnosis` | 글자 또는 없음 | 진단명 |
| `hasDiabetes` | 참/거짓 | 켜면 일기·위젯에 혈당·인슐린 칸 |
| `memorializedAt` | 시각 또는 없음 | '추억으로 간직하기'를 고른 때. 보호자가 직접 고를 때만 바뀐다(앱이 추측해서 바꾸지 않음). 고르면 그 아이의 열린 약 주기·인슐린·끼니 계획을 그 시각에 끝낸다(`activeUntil`). 되돌리면('아이 정보에서 언제든 되돌릴 수 있어요') 그때 끝낸 줄들을 같은 내용의 새 줄로 다시 연다(`activeFrom` = 되돌린 때). 추억 기간의 차례는 분모에 들어가지 않는다. |
| `profilePhotoId` | 사진 ID 또는 없음 | |

- 아이 바꾸기 목록 순서는 `createdAt`(순서 바꾸는 화면이 없음).
- 체중은 아이 칸이 아니라 기록(`weight`)으로 남긴다. 아이 등록 때 넣은 체중도 첫 체중 기록이 된다.
- **아이 지우기**: 아이와 그 아이의 기록·약 주기·인슐린·사료 바꾸기·끼니 계획·휴양 기간에 모두 `deletedAt`을 넣는다. 사진은 그 아이와의 연결(`PhotoPet`)을 지우고, 남은 아이가 없으면 사진도 지운다.

### 2-1. 휴양 기간 (`RestPeriod`)

아이 정보의 '휴양 중 · 관리 쉬기' 스위치. 켜고 끈 때를 기간으로 남겨, 지난 통계에서도 그 기간을 뺄 수 있게 한다 (2026-10-27 결정).

| 칸 | 형식 | 비고 |
|---|---|---|
| `petId` | 아이 ID | 필수 |
| `startedAt` | UTC 시각 | 스위치를 켠 때 |
| `endedAt` | UTC 시각 또는 없음 | 끈 때(이 시각 포함 안 함). 없으면 지금 휴양 중. |

- **휴양 중 = 그 아이에 `endedAt` 없는 기간이 있음.** 스위치를 켤 때는 열린 기간이 없을 때만 새 줄을 만든다. 끄면 열린 기간 모두에 `endedAt`을 넣는다(두 기기 백업을 합쳐 열린 기간이 둘이어도 함께 닫힘).
- 휴양 중에는 그 아이의 **돌봄 알림만 멈춘다**: 그 아이 약 주기의 탕약 알림, 인슐린 알림(`ringDuringQuiet`여도). 체중 재기 알림은 휴양 중이 아닌 아이만 적고, 모두 휴양 중이면 보내지 않는다. 남은 약 알림은 약 단위라(4장) 그대로 보낸다. 기쁜 날·작년 오늘 알림과 축하 카드도 그대로. 일기 탕약 줄·위젯·기록은 그대로라 휴양 중에도 기록할 수 있다.
- '추억으로 간직하기'를 고르면 열린 휴양 기간도 그 시각에 닫는다(되돌려도 다시 열지 않음).
- **휴양 기간의 차례는 '몇 번 중 몇 번'에 넣지 않는다**(6-3). 기간이 겹치면 합친 범위로 본다.

## 3. 기록 (`Record`)

모든 일기 기록을 한 테이블에 담는다. 실록 집계가 `petId + kind + day`로 한 번에 되도록.

| 칸 | 형식 | 비고 |
|---|---|---|
| `petId` | 아이 ID 또는 없음 | 1-3 참고 |
| `kind` | 아래 표의 값 | |
| `occurredAt` | UTC 시각 | 일어난 때. 시트의 '시간 바꾸기'로 바꿀 수 있다. |
| `day` | `YYYY-MM-DD` | 1-2 규칙 |
| `slotKey` | 글자 또는 없음 | 정해 둔 차례에 남긴 기록이면 그 차례 (6-1). 차례와 짝을 찾는 데 쓰고 색인을 건다. |
| `data` | JSON 글자 | 종류별 내용 (아래) |
| `auto` | 참/거짓 | 앱이 저절로 만든 기록(급식기). 화면의 '자동 기록됨'. |

기록에 붙인 사진은 `Photo.recordId`로 잇는다.

### 종류별 `data`

| `kind` | 화면 | `data` 칸 |
|---|---|---|
| `vomit` | 구토 | `contents`: `kibble`(사료 알갱이), `digested`(죽처럼 불은 사료), `liquidFoam`(액체·거품), `hairball`(헤어볼), `plant`(풀·식물), `foreign`(이물질) 중 여러 개 · `color`: `food`(사료 색), `yellow`, `clear`(투명·흰색), `green`, `red`(피), `darkRed`(검붉은·커피색) · `count`: 1, 2, 3(3번 이상) |
| `stool` | 매화 | `shape`: `hard`(단단해요), `normal`(정상), `soft`(물러요), `loose`(묽어요), `watery`(물 같아요) · `color`: `brown`, `yellowOrange`, `green`, `black`(짜장처럼), `pale`(회백색) · `signs`: `blood`, `mucus`, `foreign` 중 여러 개 |
| `urine` | 소피 | `amount`: `little`(찔끔), `normal`(보통), `much`(많음) · `color`: `paleYellow`(보통), `clear`, `darkYellow`, `pinkRed` · `signs`: `straining`(힘만 주고 안 나옴), `frequent`(자주 들락거림), `outside`(화장실 밖), `pain`(볼 때 울거나 아파함) 중 여러 개 |
| `meal` | 수라 | `result`: `all`, `some`, `none` · `foodId`(그때 먹던 사료) · `slotName`(아침·점심·저녁 같은 끼니 이름 또는 없음) |
| `snack` | 다과 | `snackId` · `amount`: 글자 또는 없음 ('얼마나 줬나요? (선택)') |
| `weight` | 옥체 | `grams`: 정수 (화면엔 kg 소수 둘째 자리로) |
| `med` | 탕약 | `scheduleId`(예정에 없던 약이면 없음) · `medicationId` · `status`: `given`(줬어요), `skipped`(건너뜀), `vomited`(먹고 토함) · `amount`, `unit` |
| `glucose` | 혈당 | `mgdl`: 정수 · `timing`: `beforeInsulin`, `afterInsulin`, `other` · `signs`: `weak`(기운 없음), `wobbly`(비틀거림·떨림), `seizure`(경련) 중 여러 개 |
| `insulin` | 인슐린 | `planId` · `units`: 소수 · `status`: `full`(다 맞음), `partial`(일부만), `skipped`(건너뜀) · `mealBefore`: `all`, `some`, `none` 또는 없음 |

- **기록은 보호자가 누른 것만 저장한다.** '건너뜀'·'먹고 토함'은 직접 눌렀을 때만 남고, 아무것도 안 누른 차례를 앱이 '안 줌'으로 저장하지 않는다. 몇 번 중 몇 번 줬는지는 6장 규칙으로 계산한다.
- `data`는 두 플랫폼 모두 JSON 글자(TEXT)로 저장한다. 실록 집계는 기간의 기록을 읽어 메모리에서 센다 — 하루 10개 남짓이라 1년이 수천 줄. 느려지면 자주 세는 값을 열로 뺀다.

## 4. 약 (`Medication`) — 약방

| 칸 | 형식 | 비고 |
|---|---|---|
| `name` | 글자 | 필수 |
| `shortName` | 글자(6자까지) 또는 없음 | 일기 탕약 버튼에 보일 짧은 이름. 없으면 `name` |
| `category` | `medicine` / `supplement` | 약 / 보조제 |
| `form` | `pill`, `powder`, `liquid`, `topical`(연고·안약), `injection` | |
| `doseAmount`, `unit` | 숫자, 단위 | '한 번에'. 약 추가에서 처음 값으로 채운다. |
| `stockAmount` | 숫자 또는 없음 | '지금 남은 양'을 적은 값 |
| `stockCountedAt` | UTC 시각 또는 없음 | 그 양을 적은 때 |
| `photoId` | 사진 ID 또는 없음 | 약 봉투·포장 사진 |
| `memo` | 글자 또는 없음 | |

- 단위 `unit`: `pill`(알), `ml`, `pack`(포), `drop`(방울). 화면의 '반 알'은 `pill` 0.5로 저장한다.
- **남은 양은 숫자를 줄여 저장하지 않고 계산한다**: `stockAmount` − (`stockCountedAt` 뒤에 남긴 그 약의 `given`·`vomited` 기록 양 합계 — 토했어도 약은 썼다). 기록을 지우면 저절로 돌아오고, 백업을 합쳐도 틀어지지 않는다. 단위가 다른 기록은 빼지 않는다.
- '남은 약 48일분' = 남은 양 ÷ 지금 쓰는 주기들의 하루 양.
- 약방의 약은 어느 아이에게 줄지 정하지 않는다. 아이와 시간은 5장(주기)에서 정한다.

## 5. 약 주기 (`MedSchedule`) — 탕약 알림 · 약 추가

| 칸 | 형식 | 비고 |
|---|---|---|
| `petId` | 아이 ID | 필수 |
| `medicationId` | 약 ID | 필수 |
| `seriesId` | 주기 ID | 같은 약 주기를 바꿔 이어 온 줄끼리 같은 값. 처음 만들 때 자기 `id`, 바꿔 만든 새 줄은 옛 줄 값을 그대로. 추억 되돌리기로 다시 연 줄도 그대로. |
| `amount`, `unit` | 숫자, 4장 단위 | '한 번에 얼마나' |
| `frequency` | 아래 다섯 가지 중 하나 | |
| `times` | `HH:mm` 목록 | 매일·며칠마다·요일에서 쓰는 먹일 시간 |
| `everyDays`, `startDate` | 정수(2 이상), 날짜 | 며칠마다. `startDate`가 첫 먹는 날이자 셈의 기준. |
| `weekdays` | 1~7 목록 (ISO, 월=1) | 요일 정해서 |
| `everyHours`, `firstAt` | 정수, UTC 시각 | 몇 시간마다 |
| `shiftOnLate` | 참/거짓 | 몇 시간마다에서 '늦게 줬을 때 다음 차례는' — 참 '준 시각부터 다시 세기'(기본), 거짓 '처음 정한 시간대로' |
| `howTo` | `plain`, `inFood`, `inTreat`, `syringe` 또는 없음 | 먹이는 방법 |
| `reminder` | 참/거짓 | 알림 보내기. 설정 `notify`의 탕약 시간과 둘 다 켜져야 울린다. |
| `leadMinutes` | 0, 5, 10, 15, 30, 60 | 알림 보낼 때 (기본 10) |
| `activeFrom` | UTC 시각 | 이 주기를 쓰기 시작한 때 |
| `activeUntil` | UTC 시각 또는 없음 | 그만 쓴 때(이 시각 포함 안 함) |

`frequency` 값: `daily`(매일), `everyNDays`(며칠마다), `weekdays`(요일 정해서), `everyNHours`(몇 시간마다), `asNeeded`(필요할 때만 — 줄·알림에 안 나옴).

- **횟수·시간·양을 바꾸면 고치지 않고 새 줄을 만든다.** 원래 줄에 `activeUntil`을 넣고 새 줄을 같은 시각의 `activeFrom`으로 만든다. 그래야 지난 기간의 '몇 번 중 몇 번'이 그때 주기로 계산되고, 실록 금색 선(6-4)도 여기서 나온다. 며칠마다는 새 줄에도 `startDate`를 그대로 옮겨 셈이 다시 시작되지 않게 한다.
- 알림·몇 분 전·먹이는 방법만 바꾸면 그 줄을 그대로 고친다(금색 선이 생기지 않게).
- 몇 시간마다의 `shiftOnLate`만 바꾸면 시간이 달라지므로 새 줄을 만들되, 금색 선은 긋지 않는다(6-4).
- **바로 앞 줄** = 같은 `seriesId`이고 `activeUntil`이 이 줄의 `activeFrom`과 같은 줄. 추억 되돌리기로 다시 연 줄은 사이가 비어 바로 앞 줄이 없다.
- 같은 `seriesId`에 열린 줄(`activeUntil` 없음)이 둘 이상이면(백업 병합 — 한 기기가 바꾸고 다른 기기가 옛 줄의 알림만 고친 경우 등) `activeFrom`이 늦은 것, 같으면 `updatedAt`이 늦은 것 하나만 쓴다(7장 인슐린과 같은 규칙).
- **짝 없는 기록**: 같은 `seriesId` 줄의 `slotKey`인데 그 줄의 차례가 아닌 `med` 기록(다른 기기가 이미 닫힌 옛 줄로 준 것이 병합으로 들어온 경우). 바꾼 날이든 아니든, 그 기록의 `day`에 남은 차례를 시간 순 앞에서부터 하나씩 처리한 것으로 친다(줄·통계 모두, `given`이면 분자에도). 바꾼 날 아래 `k`에 이미 센 기록은 다시 쓰지 않는다. 그래야 두 번 먹이지 않는다.
- **바꾼 주기는 바로 적용하되, 오늘 이미 처리한 횟수만큼은 처리한 것으로 친다** (2026-10-27 결정). 새 줄이 `times`를 쓰는 주기(매일·며칠마다·요일)이고 바로 앞 줄이 있으면, 새 줄의 `activeFrom`이 든 날(`D`)에만 이렇게 한다:
  1. 그날 새 줄 차례 = 새 줄 `times` **전부**(`activeFrom` 앞 시간도 — 6-1의 `activeFrom` 거르기를 이 날 이 줄에만 쓰지 않는다)를 시간 순으로.
  2. `k` = 같은 `seriesId`의 앞 줄들이 `D`에 가진 차례 중 `med` 기록이 있는 차례 수 + 앞 줄들의 `D` 짝 없는 기록 수(옛 종류가 몇 시간마다여도 그 차례의 `day`가 `D`면 센다).
  3. 새 줄 차례의 앞에서부터 `k`개는 **넘김**: 줄(6-2)에 안 뜨고 통계(6-3)에도 안 들어간다. 앞 줄들의 `D` 차례 중 기록 없는 것도 버린다(새 줄로 바뀌었으므로).
  - 예 1 (준 뒤 바꿈): 08:00·20:00 약을 08:00에 주고 10:00에 09:00·21:00으로 → `k`=1, 09:00 넘김, 21:00만 뜬다. 그날 분모 = 옛 08:00 + 새 21:00 = 2. 내일부터 09:00·21:00.
  - 예 2 (주기 전에 바꿈): 아무것도 안 주고 10:00에 바꾸면 → `k`=0, 옛 08:00은 버리고 새 09:00·21:00이 뜬다(09:00은 지났어도 줄에 남음). 분모 2.
  - 예 3 (하루 두 번 바꿈): 08:00에 주고 08:30에 S2, 10:00에 S3으로 → S3 기준 `k`는 S1·S2의 기록 수 = 1. S2의 넘김은 기록이 아니라 세지 않지만, S1 기록을 세므로 두 번 먹이는 일이 없다.
  - 하루 한 번 약을 이미 줬다면 `k`=1이라 오늘 몫이 끝나 자연히 내일부터 적용된다.
  - 넘김 뒤 남은 차례 중 `activeFrom` 앞 시간(이미 지난 시간)도 뜬다. 예: 08:00에 주고 10:00에 07:00·09:00·21:00으로 바꾸면 07:00 넘김, 09:00·21:00이 뜬다 — 오늘 몫이 세 번이라서다. 간격은 보호자가 판단한다(받아들임).
- 새 줄이 몇 시간마다면 이 규칙을 쓰지 않는다. 새 줄 차례는 `firstAt`부터라 `activeFrom` 뒤에만 생기고(6-1), 바꾸는 때보다 앞서 아직 안 준 옛 차례는 옛 줄에 남아 계속 뜬다(새 0번 차례와 함께 뜰 수 있음 — 받아들임).
- 같은 날 처음 만든 주기(바로 앞 줄 없음)는 6-1 거르기대로 `activeFrom` 뒤 시간부터.

## 6. 계산 규칙

### 6-1. 차례 만들기

주기 하나와 날짜(`day`) 하나로 그날의 차례를 만든다. 차례마다 `slotKey`가 있고, 그 차례에 남긴 기록은 같은 `slotKey`를 갖는다. **`slotKey`의 날짜는 기록한 날이 아니라 차례의 날짜**다(저녁 20:00 인슐린을 다음 날 06:30에 맞아도 키는 전날 날짜).

- 매일·며칠마다·요일: 그날이 먹는 날이면 `times`마다 차례 하나. `slotKey = {scheduleId}|{day}|{HH:mm}`. 현지 시각 글자로 짝지으므로 시간대를 옮겨도 이미 처리한 차례가 다시 뜨지 않는다.
  - 먹는 날: 매일은 늘 · 며칠마다는 `day ≥ startDate`이고 `(day − startDate)`가 `everyDays`로 나누어떨어질 때 · 요일은 그날 요일이 `weekdays`에 있을 때.
- 몇 시간마다: `firstAt`이 0번 차례, 그 뒤 `everyHours`씩. 늦게 줬을 때는 보호자가 고른 대로 한다 (2026-10-27 결정).
  - `shiftOnLate` 참(기본): **다음 차례도 그만큼 밀린다** = n번 차례 예정 시각 = (n−1)번 차례의 `given`·`vomited` 기록 중 가장 이른 `occurredAt`(없거나 `skipped`면 (n−1)번 예정 시각) + `everyHours`.
  - `shiftOnLate` 거짓: 언제 줬든 n번 차례 예정 시각 = `firstAt` + n × `everyHours`.
  - 둘 다 `slotKey = {scheduleId}|#{n}` — 차례 번호라서 앞 기록의 시각을 고치거나 병합으로 기록이 늘어 예정 시각이 바뀌어도 이미 남긴 기록과 짝이 풀리지 않는다. 시간 간격 약이라 시간대와 상관없다. 차례가 속한 `day`는 예정 시각으로 1-2 규칙을 쓴다.
  - 이 주기를 바꿔 새 줄을 만들면 새 줄의 `firstAt` = 고치는 화면의 '처음 먹일 때' 값. 화면은 이 칸을 미리 채워 보여 주고 보호자가 고칠 수 있다. 미리 채우는 값은 **새 줄의** `shiftOnLate`로 고르고 새 `everyHours`를 쓴다: 새 줄이 참이거나 옛 줄이 `times` 주기면 같은 `seriesId`의 마지막 `given`·`vomited` 기록 시각 + 새 `everyHours`(기록이 없으면 옛 줄의 다음 차례 예정 시각), 거짓이면 옛 줄 `firstAt` + m × 새 `everyHours`(m은 정수) 중 바꾸는 때 이상인 첫 시각('처음 정한 시간대'를 이어 감). 어느 쪽이든 바꾸는 때보다 이르면 바꾸는 때(분 단위로 올림). 바꾸는 때에 그 값으로 고정한다. 바꾸는 때보다 앞서 아직 안 준 옛 차례는 옛 줄에 남아 탕약 줄에 계속 뜬다.
  - 참일 때 지난 기록의 시각을 고치면 뒤 차례가 밀려 옛 줄 `activeUntil` 밖으로 나갈 수 있다. 그 차례에 붙어 있던 기록은 짝이 없어져 분자·분모에서 빠진다(드문 경우라 받아들임).
- 차례의 예정 시각이 `activeFrom` 이상, `activeUntil` 미만일 때만 그 주기의 차례다.
- `times`로 만든 차례의 예정 시각(`activeFrom`·휴양 기간과 견줄 UTC 순간)은 `{day}`의 `HH:mm`을 **지금 기기 시간대**로 바꾼 값이다. `HH:mm`이 06:00 전이면 `{day}` 다음 날의 그 시각이다(1-2). 인슐린·끼니 차례도 같다. 시간대를 옮겨 지난 기간을 다시 계산하면 경계 근처 차례가 안팎으로 바뀔 수 있다(받아들임).

### 6-2. 오늘 먹일 약 (일기 탕약 줄)

1. 오늘의 모든 주기(`asNeeded` 빼고, 추억으로 간직한 아이 빼고 — 휴양 중은 넣는다. 휴양 중에도 기록할 수 있어야 해서)로 차례를 만든다. 주기를 바꾼 날은 5장 '바꾼 주기' 규칙(넘김·버림)을 먼저 쓴다.
2. 같은 `slotKey`의 `med` 기록이 있는 차례는 뺀다(`given`·`skipped`·`vomited` 모두 — 이미 처리한 차례).
3. 남은 차례를 먹일 시간이 이른 순으로 보여 준다. **시간이 지나도 가리지 않는다.** 새벽 6시가 지나면 새 하루로 다시 만든다.
- **탕약 알림은 이 줄에 남은 차례에만** 예정 시각 − `leadMinutes`에 울린다. 차례가 처리·넘김·버림되거나 주기가 바뀌면 걸어 둔 알림을 다시 계산해 지운다(미리 준 약에 알림이 또 울리지 않게).

### 6-3. 몇 번 중 몇 번 (탕약 1/3, 인슐린 57/60, 다 먹은 끼니 52/60)

- 분모: 그 기간 각 날짜에 **6-1로 만든 차례 수**(그때 유효했던 주기 기준, 주기를 바꾼 날은 5장 규칙으로 넘김·버림을 뺀 것). 단 예정 시각이 휴양 기간(2-1) 안에 드는 차례는 뺀다. 끼니·인슐린 계획을 바꾼 날은 이 규칙 없이 6-1 거르기만 쓴다(그날 분모가 하루 횟수와 다를 수 있음 — 받아들임). 추억 기간은 주기가 끝나 있어 자연히 빠진다.
- 분자: 분모의 차례 중 같은 `slotKey`에 `given`(인슐린은 `full`·`partial`, 끼니는 `all`) 기록이 있는 **차례 수**. 한 차례에 기록이 둘이어도 하나로 센다. 예정에 없던 약(`slotKey` 없음)은 세지 않는다. 그래서 분자가 분모보다 커지지 않는다.
- `vomited`는 분자에 넣지 않고 실록에 따로 센다('먹고 토함'은 실록에 따로 세요). 인슐린의 '밥 안 먹고 맞은 날'은 `mealBefore = none`인 `full`·`partial` 수. 이 둘은 일어난 일을 세는 것이라 휴양 기간 기록도 센다.

### 6-4. 바꾼 날 (실록 금색 선)

- 사료: `FoodChange.startedOn`.
- 약: 같은 `seriesId` 안에서 판단한다. (1) 시리즈 첫 줄의 `activeFrom`(약 시작), (2) 바로 앞 줄이 있는 줄의 `activeFrom` 중 바로 앞 줄과 `frequency`·`times`·`everyDays`·`weekdays`·`everyHours`·`amount`·`unit` 가운데 하나라도 다른 때(바꿈 — `shiftOnLate`·`firstAt`만 다르면 긋지 않음), (3) 시리즈 마지막 줄의 `activeUntil`(약 끝). 추억으로 끝났다가 되돌려 다시 연 경계에는 긋지 않는다.

### 6-5. 혈당 곡선

- 같은 아이·같은 `day`의 `glucose` 기록을 시각 순으로 이은 것. 묶음 ID를 따로 두지 않는다('같은 날 여러 번 재면 곡선으로 묶여요').

## 7. 인슐린 (`InsulinPlan`) — 당뇨 아이만

| 칸 | 형식 | 비고 |
|---|---|---|
| `petId` | 아이 ID | |
| `name` | 글자 또는 없음 | '몰라도 돼요' |
| `syringe` | `u40`, `u100`, `unknown` | |
| `slots` | `{time: HH:mm, units: 소수}` 목록 | 맞는 시간과 양 |
| `ringDuringQuiet` | 참/거짓 | 밤 알림 쉬기 중에도 울림. 인슐린 알림 자체는 설정 `notify`의 인슐린 시간으로 켜고 끈다. |
| `leadMinutes` | 0, 5, 10, 15, 30, 60 | |
| `activeFrom`, `activeUntil` | UTC 시각 | 5장과 같은 방식(시간·양을 바꾸면 새 줄) |

- 차례와 `slotKey`는 6-1의 '매일'과 같다: `{planId}|{day}|{HH:mm}`.
- **지금 차례**: 각 차례는 '자기 시간 1시간 전'부터 '다음 차례 시간 1시간 전'까지가 자기 구간이다. 예: 08:00·20:00이면 07:00~19:00은 아침 차례, 19:00~다음 날 07:00은 저녁 차례.
- 일기의 '맞음 · 2단위'는 지금 차례의 양으로 `insulin` 기록(`full`)을 만든다. '건너뜀'은 `skipped`.
- **두 번 맞히기 방지**: 지금 차례 구간 안에 그 아이의 `insulin` 기록이 하나라도 있으면(어느 계획에서 왔든, `skipped` 포함) 버튼은 맞음 버튼이 아니라 처리한 상태(`full`·`partial`은 '✓ 08:02 맞음', `skipped`는 '– 08:02 건너뜀')로 바뀌고 구간이 끝날 때까지 그대로다. 계획을 그날 바꿔도 이 규칙이라 다시 뜨지 않는다.
- 같은 아이에 열린 계획(`activeUntil` 없음)이 둘 이상이면(두 기기 백업을 합친 경우) `activeFrom`이 늦은 것, 같으면 `updatedAt`이 늦은 것 하나만 쓴다. 끼니 계획(`MealPlan`)도 같다 — 안 그러면 분모가 두 배가 된다.

## 8. 사료·다과·끼니

**사료 (`Food`)**: `name`, `ingredientPhotoId`.

**사료 바꾸기 (`FoodChange`)**: `petId`, `foodId`, `startedOn`(먹기 시작한 날), `method`: `gradual`(조금씩 섞어서) / `atOnce`(한 번에), `finishedOn`(보호자가 '다 바꿨어요'를 누른 날 또는 없음), `checkedStep`(마지막으로 '아직이에요'를 누른 단계: 0·7·10·12·14). 지금 먹는 사료 = 그 아이의 가장 늦은 `startedOn`.

**수라 바꾸기 기간과 '사료 다 바꿨나요?'** (2026-10-27 결정)
- 먹기 시작한 날을 1일째로 세어(1-2 하루 기준), **7·10·12·14일째**에 문안 화면에 '사료 다 바꿨나요?' 카드를 띄운다. 휴대폰 알림은 보내지 않는다.
- 카드는 그 단계 날부터 다음 단계 전날까지 보이고, '아직이에요'를 누르면 `checkedStep`을 그 단계로 바꿔 다음 단계까지 숨긴다.
- '다 바꿨어요'를 누르면 `finishedOn`을 넣고 더 묻지 않는다.
- 수라 바꾸기 기간 = `startedOn`부터 `finishedOn` 전날까지, `finishedOn`이 없으면 **14일째까지**. 이 기간에 준 다과는 실록에 따로 표시한다(다과 화면 '지금은 수라 바꾸기 기간이에요').
- 카드와 사료 바꾸기 시트에서 아이 종에 맞는 '사료 바꾸는 법' 레이어를 연다(고양이: 길게는 40일, 강아지: 7일 — 미국 동물병원협회 자료).
- `method = atOnce`여도 같은 규칙을 쓴다(바꾼 뒤 잘 먹는지 확인하는 기간).

**다과 (`Snack`)**: `name`, `kind`: `lickable`(짜 먹는 간식), `freezeDried`, `jerky`(져키·스틱), `wet`(캔·파우치), `prescription`(처방 간식), `human`(사람 음식) · `okDuringFoodChange`(수라 바꾸기 중에도 괜찮은 간식) · `ingredientPhotoId`.

**끼니 계획 (`MealPlan`)**: `petId`, `mode`: `direct`(직접 급여) / `feeder`(급식기, 수라간), `slots`: `{name, time: HH:mm}` 목록, `activeFrom`, `activeUntil`(UTC 시각, 5장과 같은 방식).
- 수라 화면의 '아침 · 08:10', '저녁 · 아직 기록 전'과 실록의 '다 먹은 끼니 52/60' 분모가 여기서 나온다. 끼니 차례의 `slotKey = {planId}|{day}|{HH:mm}`.
- 일기 빠른 버튼·위젯으로 남긴 `meal` 기록은 7장과 같은 구간 규칙으로 **지금 끼니 차례**에 넣는다. 그 차례에 이미 기록이 있으면 `slotKey` 없이 남긴다(분자에 안 들어가는 추가 식사). 수라 화면에서 끼니를 골라 남기면 그 끼니 차례.
- 급식기 모드면 끼니 시간이 되면 `meal` 기록(`result = all`, `auto = true`)을 고정 ID(1-5)로 만든다 — 두 기기가 각자 만들어도 하나로 합쳐진다.
- 시간을 바꾸면 그 시각에 새 줄을 만든다 = '바꾼 시간은 아직 지나지 않은 끼니부터 바로 적용돼요. 지난 기록은 그대로예요.'

## 9. 사진 (`Photo`, `PhotoPet`)

| 칸 | 형식 | 비고 |
|---|---|---|
| `takenAt` | UTC 시각 | 찍은 때(사진 정보에서, 없으면 올린 때) |
| `localDate` | `YYYY-MM-DD` | 찍은 곳의 달력 날짜. '작년 오늘'·나이 표시용 (1-2 예외) |

| `kind` | `normal` / `body` | `body` = 체형 비교용 |

## 10. 설정

**함께 쓰는 설정 (`Setting`, 고정 ID 하나, 백업·병합에 들어감)**: `quietHours`(밤 알림 쉬기 켜짐·시작·끝 — 이 시간의 알림은 보내지 않고 버린다. 줄·카드는 그대로), `notify`(탕약 시간·인슐린 시간·남은 약·체중 재기·기쁜 날·작년 오늘 켜짐), `weightReminder`(요일·시각, 기본 일요일 10:00), `lowMedDays`(남은 약 알림 기준 일수, 기본 3), `celebrateTone`(`joseon` / `plain` — 축하 카드 문구).

- 묶음 칸 이름 (2026-10-28 4-1에서 정함): `quietHours` = `{enabled, start, end}`(`HH:mm`) · `notify` = `{medTime, insulinTime, lowMed, weighIn, goodDay, lastYearToday}`(참/거짓) · `weightReminder` = `{weekday(ISO), time(HH:mm)}`. 밤 알림 쉬기·알림 켜짐·`celebrateTone`의 처음 값은 아직 안 정함 — 코드는 임시로 꺼짐 22:00~07:00 · 모두 켜짐 · `joseon`, 설정 화면 때 디자인과 맞춘다.

**이 기기만의 설정 (백업에 안 넣음)**: iOS `UserDefaults`, 안드로이드 DataStore에 둔다. 아이폰 백업을 안드로이드로 가져와도 'iCloud에 백업' 같은 값이 넘어오지 않게.
- 백업: `backupTarget`(`icloud` / `googleDrive` / `none`), `autoBackupNightly`, `backupPhotos`, `wifiOnly`, `lastBackupAt`
- 기타: `lastPetId`(마지막으로 보던 아이), `lastOpenedAt`(앱을 오래 안 열면 알림을 줄이는 데 씀), `shownCelebrations`(이미 보여 준 축하 카드 `{petId}|{종류}|{날짜}` 목록)

**축하 카드** (2026-10-27 결정): 그날 앱을 처음 열 때 **한 번만** 띄운다. 그날 앱을 안 열면 지나간다(다음 날 늦게 띄우지 않음). 날짜는 기기 현지 달력 날짜.

결제 여부는 저장하지 않는다. 앱이 켜질 때 App Store·구글 플레이에 묻는다(구매 복원 포함).

## 11. 백업과 병합

- 백업 파일 = 머리 정보 + 위 모든 표(지운 줄 포함)를 JSON 배열로 + 사진 파일(`backupPhotos`일 때만). 본인 iCloud Drive·구글 드라이브에 저장.
- 머리 정보: `schemaVersion`(지금 1), `createdAt`, `appVersion`, `platform`, `includesPhotos`, `counts`(기록 일수·사진 수 — '기록 1,248일치 · 사진 312장'). 구조가 바뀌면 `schemaVersion`을 올리고 가져올 때 옮기는 규칙을 이 문서에 적는다.
- **가져오기는 덮어쓰지 않고 합친다.** 같은 `id`가 양쪽에 있으면:
  1. 어느 한쪽이라도 `deletedAt`이 있으면 **지운 쪽이 늘 이긴다**('되돌릴 수 없어요'와 맞추려고).
  2. 아니면 `updatedAt`이 늦은 쪽을 남긴다.
- 이 기기에 없는 `id`는 그대로 가져온다. 사진 파일은 이긴 줄이 지운 줄이 아니고 이 기기에 파일이 없을 때만 복사한다. 줄은 있는데 파일이 없으면(사진 없이 만든 백업) '사진 파일 없음'으로 보여 주고, 나중에 파일이 든 백업을 가져오면 채운다.
- 시각 비교는 각 기기 시계를 믿는다. 기기 시계가 크게 틀리면 늦게 고친 쪽이 질 수 있다(v1.0은 한 사람이 쓰는 백업이라 받아들임).
- 휴양 기간은 줄마다 이 규칙으로 합친 뒤 열린 기간이 하나라도 있으면 휴양 중이다. 한 기기에서 끄고 다른 기기에서 따로 켜 둔 채 합치면 휴양 중으로 보인다(켜 둔 쪽이 남음 — 받아들임).
- 같은 규칙을 다음 버전 서버 동기화에도 그대로 쓴다.

## 12. 디자인과 맞춘 것·남은 것

- **수라 결과 문구 통일 (2026-10-27 반영)** — 일기·수라·급식기·인슐린 시트 모두 '다 먹음·남김·안 먹음' = `all`·`some`·`none`.
- **구토 빠른 버튼 (2026-10-27 반영)** — '사료·불은 사료·거품' = 시트의 '사료 알갱이'(`kibble`)·'죽처럼 불은 사료'(`digested`)·'액체·거품'(`liquidFoam`). 버튼은 줄 폭 때문에 줄인 이름, 화면 읽기 이름은 시트 이름 그대로.
- **인슐린 '건너뜀'을 누른 뒤 상태 (2026-10-27 반영)** — 보드 `RecordInsulinSkip`. 처리한 칸은 흰 바탕·회색 글자로 '– 08:02 건너뜀'(맞음은 남색 바탕 '✓ 08:02 맞음'), 눌러서 고치기, 알림 줄 '인슐린 건너뜀 · 08:02 · 되돌리기'.
- **실록 그래프 바꾼 날 이름표 (2026-10-27 반영)** — 금색 선의 이름표('사료'·'탕약')는 선 왼쪽에 붙인다. 그래프는 최근 날짜부터 보이므로, 화면 밖 선의 이름표만 삐져나와 잘리는 일을 막는다. 구현 메모: 기간 맨 앞까지 넘겼을 때 첫날 근처 선은 이름표가 왼쪽 끝에서 잘릴 수 있으니, 그때만 오른쪽에 붙인다.
- **몇 시간마다 '늦게 줬을 때' (2026-10-27 반영)** — 보드 `MedAddHours`. '늦게 줬을 때 다음 차례는' 라디오 두 개: '준 시각부터 다시 세기'(기본)·'처음 정한 시간대로' = `shiftOnLate` 참·거짓.
